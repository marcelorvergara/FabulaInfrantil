# Story Sharing

> Summary + API/data model → [CLAUDE.md](CLAUDE.md#story-sharing)

Shared stories render as a normal Next.js SSR page (`pages/historias/[storyId].tsx`) on `fabulainfantil.com`, not a separate site. This replaced an older `story.fabulainfantil.com` EJS page (App Engine) that had a real deadlock: `POST /shareStory` only wrote text to Firestore, and image copying only happened lazily on first page view — but the frontend polled a `/ready` endpoint that could never turn true until that same first view happened, so shares reliably burned the full poll timeout before opening a slow page.

**Fix: image copy is now synchronous at share-creation time.** `POST /shareStory` (`ShareStoryController.shareStory`) writes the Firestore doc, then `await`s copying all 3 images to their permanent GCS location before responding — the 201 response *is* the readiness signal. `pages/index.tsx`'s `shareStory()` no longer polls; it awaits the POST directly. Doc/image shapes are in [CLAUDE.md → Data Models](CLAUDE.md#data-models).

**Image storage** (`shareStory.repo.ts`):
- Permanent images live at `images-gen/{storyId}/image-{1,2,3}.{jpg|png}` — the extension matches the actual fetched `Content-Type` (`image/jpeg`→`jpg`, `image/png`→`png`; anything else, e.g. `image/webp`, is rejected outright), not hardcoded. This replaced an earlier version of this feature that named files `.webp` while actually storing raw jpg/png bytes with no `Content-Type` metadata at all — silently broke Open Graph link previews.
- `copyOneImage` checks whether the permanent file already exists (both `.jpg` and `.png` candidates) **before** touching the source URL at all. This matters because the source is a temp URL (`images-gen/temp/{uuid}.{ext}`, produced by `GenerateImageController`) that can expire — an image already durably copied must never depend on that temp URL still being reachable, or a perfectly good permanent copy would start failing once its original temp URL goes stale.
- Source URLs are validated against an allowlist (`^https://storage\.googleapis\.com/images-gen/temp/[A-Za-z0-9-]+\.(jpg|jpeg|png)$`) before ever being fetched — `storeImage`'s URL comes straight from a client-supplied POST body, so this closes off an arbitrary server-side-fetch gap. Fetches are also capped at 10MB.

**Legacy-doc backfill** (`getStoryData`, used by `pages/historias/[storyId].tsx`'s `getServerSideProps`): docs shared before this change — or a doc where a prior backfill attempt only partially succeeded — have no `imageExts`, or have some `null` slots. Rather than a separate migration script, `GET /shareStory/:storyId/data` recovers the original temp URLs already stored in the doc (`docData.story.firstImage` etc.) and backfills on demand via `storeImagesSettled`, a `Promise.allSettled` variant that tolerates individual image failures — a story is still worth showing even if one source image expired. Results are persisted **including `null` slots**, so an unrecoverable image isn't refetched on every future view; only the still-`null` slots are retried on subsequent visits.

**Legacy link redirect**: `GET /shareStory/:storyId` (the old `story.fabulainfantil.com` route) now issues a `302` (not `301`) redirect to `https://fabulainfantil.com/historias/:storyId`. Deliberately temporary — a `301` gets cached by browsers/CDNs/crawlers and is hard to undo if anything needs correcting in the first few days. **Deferred fast-follow, not done yet**: flip to `301`, and delete `back-end/public/index.ejs` + the `ejs` dependency, once the new flow has baked in production without issues.

**Share-URL popup-blocker safety** (`pages/index.tsx`'s `shareStory()`): the share button opens a blank tab (`window.open("", "_blank")`) as the *first synchronous statement*, before any `await` — awaiting the POST first (now genuinely slow, since it does real image-copy work) would make browsers, Safari especially, treat the later `window.open` as a blocked popup. The whole upload is wrapped in try/catch; on failure, or if the popup was blocked outright, it falls back to a visible "Abrir link ↗" anchor in `BackCover.tsx` (`shareUrl` prop) instead of leaving a blank tab stuck open with the button frozen on "Preparando link...".

**Environment-correct share URLs**: share links and the `Cover.tsx` history list both build their URL via `getSiteBaseUrl()` (`helpers/generalFunctions.ts` — `window.location.origin` on the client, hardcoded prod domain as an SSR-time fallback), not a hardcoded `fabulainfantil.com` — otherwise local/preview testing would always open production. The SSR page's own `<Head>` canonical/OG URLs stay hardcoded to the production domain on purpose, since those describe the page's real public identity regardless of where it happened to render.

**Verify with**: `tsc --noEmit` + `npm run build` on both sides (confirm `historias/[storyId]` shows `ƒ (Dynamic)` in the route summary, not `○ (Static)`); manually exercise `POST /shareStory` → `GET /:id/data` → `GET /:id` (302 redirect); paste a resulting URL into a link-preview validator (Twitter Card Validator / Facebook Sharing Debugger) to confirm `og:image` loads with the correct `Content-Type`.
